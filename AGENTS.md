# Repository guidance

## Commands and verification

- Use Bun (`bun@1.4.2` in `package.json`) and `bun.lock`. Shared dependency versions live in the root workspace catalog; Vite is overridden to Vite+ core.
- Initial setup: `bun install`, then `bun run dev:setup` to configure Convex. Installation also generates web env types.
- `bun run dev` runs the workspace `dev` scripts: Convex and Alchemy. `bun run dev:web` starts bare Vite on port 3001; `bun run dev:server` starts only Convex.
- `bun run lint` uses Vite+ exclusions for generated/build files. `bun run check` instead runs `oxlint && oxfmt --write`: it modifies files and does **not** typecheck, despite the README's script summary.
- `bun run check-types` covers web, UI, and infra; the backend has no `check-types` script. Check backend types explicitly with `bunx tsc --noEmit -p packages/backend/convex/tsconfig.json`.
- For focused checks, run `bun run check-types` from `apps/web`, `packages/ui`, or `packages/infra`. The web script runs `vp build` before `tsc --noEmit`, generating the route tree needed on a fresh checkout.
- No test scripts, test configuration, or test files currently exist; Testing Library dependencies alone do not establish a test workflow.

## Wiring and ownership

- The web app uses TanStack Start file routes in `apps/web/src/routes`. `src/router.tsx` wires Convex into TanStack Query and SSR; `routes/__root.tsx` supplies the auth token and provider. Preserve both server query auth and client provider wiring when changing authentication.
- Better Auth runs in Convex (`packages/backend/convex/auth.ts`, `http.ts`). The web catch-all `routes/api/auth/$.ts` forwards GET/POST through `src/lib/auth-server.ts`; it is not a separate auth database.
- Shared UI uses Base UI-backed shadcn (`base-lyra`), not Radix primitives. Import via `@sarvesh-blog/ui/components/<name>`; design tokens/global CSS belong in `packages/ui/src/styles/globals.css`, imported by the web's `src/index.css`.
- Both `components.json` files route shared primitives to `packages/ui`. The README's shared-component CLI uses `-c packages/ui`; app-specific components belong in `apps/web/src/components`.

## Environment and generated files

- Bun's automatic env loading is disabled in root and web `bunfig.toml`. Web code reads `ENV` from `src/env.public.ts` (Vite's `import.meta.env`); `src/env.ts` is generated Varlock types/runtime access, not the web runtime entrypoint.
- Web configuration requires `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL` in `apps/web/.env`; they are distinct API and HTTP/auth endpoints. Convex auth separately requires deployment env `SITE_URL` for its base URL and trusted origin.
- Edit `apps/web/.env.schema`, then run root `bun run env:generate`; this only generates types and does not load env values for later commands. Do not hand-edit `apps/web/src/env.ts`.
- Do not hand-edit `apps/web/src/routeTree.gen.ts` or `packages/backend/convex/_generated/*`. The route tree is ignored and generated by the Start build/dev plugin; Convex generates its API/model/server bindings.
- `packages/infra/.env.schema` imports web env configuration. `packages/infra/alchemy.run.ts` loads it with `varlock/auto-load`; run standalone Varlock-dependent tools from the schema-owning directory.

## Deployment

- Root `bun run deploy` / `bun run destroy` invoke Alchemy in `packages/infra`. The actual Cloudflare website definition is `packages/infra/alchemy.run.ts`, with `rootDir: "../../apps/web"`, `nodejs_compat`, and the two Convex URLs supplied as env inputs.
